# TeleSentinel infrastructure

| Stack | Role | What it creates |
|---|---|---|
| `azure/` | Primary | VNet, AKS (OIDC + workload identity), ACR, PostgreSQL Flexible Server (pgvector), Redis (private endpoint), Cosmos DB Mongo API, Azure OpenAI (chat + embeddings), Event Hubs (Kafka), Key Vault |
| `gcp/` | AI + analytics | BigQuery dataset and partitioned tables, Vertex AI service account, keyless access from AKS via Workload Identity Federation, staging bucket |
| `aws-dr/` | Disaster recovery (pilot light) | VPC, EKS with zero nodes, ECR, RDS PostgreSQL, ElastiCache, S3 backups, Route 53 failover |
| `modules/azure-data` | Shared module | PostgreSQL + Redis + Cosmos used by `azure/` |

## Usage (each stack is independent, with its own state)
```bash
cd infra/terraform/azure
terraform init -backend-config=backend.hcl
terraform plan  -var-file=envs/dev.tfvars
terraform apply -var-file=envs/dev.tfvars
```
Order: `azure` first, then `gcp` (pass `aks_oidc_issuer_url` from the Azure output), then `aws-dr`.

## Notes
- Event Hubs uses Kafka protocol (SASL_SSL, port 9093, username `$ConnectionString`). Topics are Event Hubs created by Terraform; the services' `NewTopic` auto-creation is not needed there.
- Secrets are generated by Terraform and stored in Key Vault. Mount them into pods with the Secrets Store CSI driver or External Secrets; do not copy them into Helm values.
- Model names, versions, and region availability change often. Check the provider docs before applying `chat_model_*` and `embedding_model_*`.
- Not validated here (no Terraform binary in my environment): run `terraform fmt -recursive && terraform validate` per stack and review the plan before apply.
